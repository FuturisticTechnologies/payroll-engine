# 06 - API Design

## 1. Principles

- REST over JSON. Resources map to nouns; verbs are HTTP methods.
- Versioned URL prefix: `/api/v1`.
- Stable identifiers: UUIDs in URLs and payloads.
- OpenAPI source of truth: `/openapi.json` is generated by FastAPI.
- Idempotent creates: create endpoints accept `Idempotency-Key`.
- Tenant-aware design: tenant-scoped resources carry `tenant_id`.

## 2. URL Conventions

```text
/api/v1/<collection>
/api/v1/<collection>/{id}
/api/v1/<collection>?tenant_id=<uuid>&limit=100&offset=0
```

Collections are lowercase plural nouns. Filters live in query string.

## 3. Current Endpoints

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/` | Service identity banner |
| `GET` | `/api/v1/health` | Liveness |
| `GET` | `/api/v1/health/ready` | Readiness, database reachable |
| `GET` | `/api/v1/meta/version` | Build version |
| `GET` | `/api/v1/meta/milestone` | Current SOW milestone |
| `POST` | `/api/v1/auth/login` | Password to JWT |
| `GET` | `/api/v1/tenants` | List employer tenants |
| `POST` | `/api/v1/tenants` | Create employer tenant |
| `GET` | `/api/v1/tenants/{tenant_id}` | Fetch one tenant |
| `GET` | `/api/v1/employees` | List employees, optionally by tenant |
| `POST` | `/api/v1/employees` | Create employee |
| `GET` | `/api/v1/employees/{employee_id}` | Fetch one employee |
| `GET` | `/api/v1/employment-contracts` | List employment contracts |
| `POST` | `/api/v1/employment-contracts` | Create employment contract |
| `GET` | `/api/v1/employment-contracts/{contract_id}` | Fetch one contract |
| `GET` | `/api/v1/framework` | Pay frequencies, contract types, NI categories, roles and permissions |

Interactive documentation is available at `/docs` and `/redoc`.

## 4. Authentication

Milestone 2 retains `/auth/login` for first-party login and returns access and
refresh JWTs. Tenant, employee, contract and framework endpoints require bearer
tokens and persisted RBAC permissions.

```http
Authorization: Bearer <access_token>
X-Tenant-ID: <tenant_uuid>
```

## 5. Idempotency

Create endpoints support:

```http
Idempotency-Key: client-generated-stable-key
```

Rules:

- The key is scoped to HTTP method and path.
- The request payload is hashed.
- Repeating the same request returns the original response.
- Reusing the same key with a different payload returns `409 Conflict`.
- The key is reserved before the resource write and completed in the same
  transaction to avoid concurrent retry races.
- Keys are stored in `idempotency_keys` for future expiry/cleanup policy.

## 6. Example Payloads

### Create Employee

```json
{
  "first_name": "Jane",
  "last_name": "Doe",
  "email": "jane.doe@example.com",
  "national_insurance_number": "AB123456C",
  "tax_code": "1257L",
  "ni_category": "A",
  "employment_start_date": "2026-05-01",
  "job_title": "Payroll Officer"
}
```

If `tenant_id` and `employee_number` are omitted, the API uses the default
development tenant and generates an employee number.

### Create Employment Contract

```json
{
  "employee_id": "00000000-0000-4000-8000-000000000999",
  "contract_type": "permanent",
  "pay_frequency": "monthly",
  "annual_salary": "42000.00",
  "weekly_hours": "37.50",
  "effective_from": "2026-05-01",
  "currency": "GBP",
  "is_primary": true
}
```

## 7. Errors

Current API responses use FastAPI's default error envelope:

```json
{
  "detail": "Tenant not found"
}
```

Problem Details (`application/problem+json`) remains planned for a later API
consistency milestone.

## 8. Versioning and Deprecation

- Backwards-compatible changes ship inside `/api/v1`.
- Breaking changes require `/api/v2` with a 6-month overlap period.
- Deprecation notice is delivered through `Deprecation` and `Sunset` headers.

## 9. Rate Limiting

Redis-backed rate limiting is still planned. The M2 schema and API are ready
for actor and tenant-aware policy, but enforcement is not yet enabled.
